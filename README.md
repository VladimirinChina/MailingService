# MailingService

Веб-приложение на Django для управления рассылками: получатели, сообщения, рассылки, отправка писем по требованию, история попыток и статистика. Есть регистрация с подтверждением email, восстановление пароля, разграничение прав (пользователь и менеджер) и кеширование.

## Возможности

- **Получатели**: добавление, просмотр, редактирование и удаление (email, Ф. И. О., комментарий).
- **Сообщения**: тема и тело письма, полный CRUD.
- **Рассылки**: период отправки (начало и окончание), сообщение, список получателей. Статус (`Создана`, `Запущена`, `Завершена`) вычисляется динамически по текущему времени.
- **Отправка по требованию**: кнопкой «Отправить сейчас» в интерфейсе или командой из консоли. Письмо уходит каждому получателю, для каждого создаётся запись о попытке (`Успешно` / `Не успешно` с ответом почтового сервера). Попытки сохраняются одним запросом через `bulk_create`.
- **Валидация**: время начала не может быть в прошлом и должно быть раньше времени окончания; вне периода рассылки отправка запрещена с сообщением об ошибке.
- **Главная страница**: общее число рассылок, число активных рассылок, число уникальных получателей.
- **Статистика пользователя**: успешные и неуспешные попытки, количество отправленных сообщений, разбивка по рассылкам.
- **Аутентификация**: регистрация с подтверждением email по ссылке, вход, выход, восстановление пароля.
- **Роли и права** (см. ниже).
- **Кеширование**: серверное и клиентское (см. ниже).

## Стек

- Python 3.14, Poetry
- Django 6.1
- SQLite (по умолчанию)
- Кеш Django: встроенный в память или Redis
- Bootstrap 5 (подключается через CDN)
- Качество кода: black, flake8, mypy

## Структура проекта

```
config/             настройки проекта, корневые URL
users/              модель пользователя (вход по email), регистрация, подтверждение email,
                    восстановление пароля, список пользователей и блокировка
mailings/           получатели, сообщения, рассылки, попытки, отправка, статистика, кеш
  services.py       логика отправки рассылки
  cache.py          получение данных из кеша и сброс кеша
  signals.py        сброс кеша при изменении данных
templates/          шаблоны (base.html, mailings/, users/)
```

## Установка и запуск

```bash
git clone <URL репозитория>
cd MailingService

poetry install
cp .env.example .env        # затем заполните значения в .env

poetry run python manage.py migrate
poetry run python manage.py createsuperuser
poetry run python manage.py create_manager_group

poetry run python manage.py runserver
```

Приложение будет доступно на `http://127.0.0.1:8000/`.

После изменения `.env` сервер нужно перезапустить: автоперезагрузка Django следит только за `.py`-файлами.

## Переменные окружения (`.env`)

| Переменная | Назначение | Пример |
|---|---|---|
| `SECRET_KEY` | секретный ключ Django, **обязательная** переменная | см. ниже |
| `DEBUG` | режим отладки (по умолчанию 'False') | `True` |
| `ALLOWED_HOSTS` | разрешённые хосты через запятую | `localhost,127.0.0.1` |
| `EMAIL_BACKEND` | бэкенд отправки почты | `django.core.mail.backends.smtp.EmailBackend` |
| `EMAIL_HOST` | SMTP-сервер | `smtp.gmail.com` |
| `EMAIL_PORT` | порт SMTP | `587` |
| `EMAIL_USE_TLS` | использовать TLS | `True` |
| `EMAIL_USE_SSL` | использовать SSL (не вместе с TLS) | `False` |
| `EMAIL_HOST_USER` | логин (адрес отправителя) | `name@gmail.com` |
| `EMAIL_HOST_PASSWORD` | пароль приложения | см. ниже |
| `DEFAULT_FROM_EMAIL` | адрес «От кого» | `name@gmail.com` |
| `CACHE_BACKEND` | бэкенд кеша (необязательно) | `django.core.cache.backends.redis.RedisCache` |
| `CACHE_LOCATION` | расположение кеша (необязательно) | `redis://127.0.0.1:6379/1` |

### Почта

Для разработки можно оставить `EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend`: письма не отправляются, а печатаются в терминале, где запущен сервер (в этом режиме попытки всегда будут «Успешно»).

Для реальной отправки через Gmail нужны двухэтапная аутентификация и **пароль приложения** (не обычный пароль аккаунта): его указывают в `EMAIL_HOST_PASSWORD` без пробелов. Адрес в `DEFAULT_FROM_EMAIL` должен совпадать с `EMAIL_HOST_USER`.

### Часовой пояс

Время рассылок вводится и показывается в часовом поясе из `TIME_ZONE` в `config/settings.py`. Поменяйте его под свой, иначе введённое время будет трактоваться в чужом поясе и рассылка может оказаться вне периода отправки.

## Отправка рассылки

**Через интерфейс:** страница рассылки, кнопка «Отправить сейчас».

**Из консоли:**

```bash
poetry run python manage.py send_mailing <id рассылки>
```

Если текущее время вне периода `start_time` – `end_time` или рассылка отключена менеджером, отправка не выполняется и выводится сообщение об ошибке.

## Роли и права

| Роль | Возможности |
|---|---|
| Пользователь | создание, просмотр, редактирование и удаление **своих** получателей, сообщений и рассылок; статистика по своим рассылкам |
| Менеджер | просмотр **всех** получателей, сообщений и рассылок (без редактирования и удаления чужих данных); просмотр списка пользователей; блокировка и разблокировка пользователей; отключение и включение рассылок |
| Администратор | всё перечисленное и доступ к админ-панели `/admin/` |

Группа «Менеджеры» создаётся командой `create_manager_group`. Чтобы сделать пользователя менеджером, добавьте его в эту группу в админ-панели.

## Кеширование

**Серверное.** Статистика на главной и личная статистика пользователя хранятся в кеше Django (TTL 60 секунд). Кеш сбрасывается при создании, изменении и удалении рассылок и получателей (через сигналы) и после отправки рассылки. По умолчанию используется кеш в памяти. Для Redis:

```bash
brew install redis && brew services start redis
poetry add redis
```

и две переменные `CACHE_BACKEND` и `CACHE_LOCATION` в `.env` (см. таблицу выше). Менять код не нужно.

**Клиентское.** Главная страница отдаётся с заголовками `Cache-Control: private, max-age=60` и `Vary: Cookie`: браузер может держать её минуту, а после входа или выхода получит свежую версию. Проверить: `curl -I http://127.0.0.1:8000/`.

## Известные упрощения

- Блокировка пользователя реализована через `is_active`, как и неподтверждённый email. В дальнейшем её можно вынести в отдельное поле.
- По умолчанию используется SQLite; другая СУБД подключается заменой настройки `DATABASES`.
- email получателя уникален в рамках одного пользователя.
